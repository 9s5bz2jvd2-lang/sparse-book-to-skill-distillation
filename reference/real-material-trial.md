# Authorized real-material readiness trial

## Purpose and evidence boundary

This procedure accepts a local authorized source, human/agent-authored semantic artifacts, and independently authored query gold without placing any real book or paid/private corpus in this repository. Deterministic code handles bytes, ordering, state, validation, routing, and comparison. It does **not** understand the material, author semantic artifacts, invent query gold, or grade answer meaning.

A passing trial can establish structural source coverage, interruption-safe queue progress, artifact/provenance integrity, deterministic route recall against the supplied gold, and exact source-chunk load correctness. It cannot by itself establish faithful interpretation, complete domain knowledge, answer quality, professional safety, copyright permission, PDF/OCR fidelity, latency, cost, or performance on other material.

## 1. Prepare an isolated workspace

Keep the source, workspace, authored bundle, gold, and report outside the repository when they are private or redistribution-restricted.

```bash
python3 scripts/real_material_trial.py prepare \
  --source /authorized/local/material \
  --workspace /private/local/trial-workspace \
  --chunk-lines 80
```

This creates the normal manifest/original/text/chunk files plus:

- `review-state.json`: manifest- and queue-plan-bound ordered progress;
- `distilled/semantic-review.json`: a pending authored quality declaration;
- one pending record per chunk.

PDF remains opt-in through `--allow-pdftotext`; extraction fidelity still needs human review.

## 2. Review in durable contiguous batches

```bash
python3 scripts/review_queue.py next \
  --workspace /private/local/trial-workspace \
  --batch-size 3
```

Read every returned `chunk_path` completely and author its `artifact_path` plus any L3 file. Repeating `next` after interruption returns the same active batch. It does not advance. To commit the longest valid contiguous authored prefix of the active slice:

```bash
python3 scripts/review_queue.py checkpoint \
  --workspace /private/local/trial-workspace
```

Then call `next` again. The state contract permits only an ordered completed prefix followed by one contiguous active slice. Checkpoint scans the active slice in order: the first pending record ends the committable prefix (a pending head fails with `incomplete_review_batch` and commits nothing), an invalid non-pending prefix record hard-fails with state unchanged, and authored records past a pending gap remain active for a later checkpoint. Prefix checks cover structure, identity, hash, provenance, and required content shape only — not semantic truth. A completed record outside the active slice fails with `out_of_order_review`; tampered plan/progress fails with `review_state_mismatch`. Finalization may fast-forward only after it has inspected every queue record, which supports a complete external authored bundle without allowing a skipped chunk or a false completion flag.

Generated scale tests exercise this mechanism with redistributable synthetic text only. They are not semantic evidence.

## 3. Author the explicit semantic-review contract

After reviewing all records, L3 modules, and shared core against the source, replace `distilled/semantic-review.json` using `assets/semantic-review-template.json` and `contracts/semantic-review.v2.schema.json`.

The declaration must:

- bind the exact source-manifest SHA-256;
- list every queue chunk exactly once in queue order;
- identify whether the reviewer was a human, agent, or both;
- affirm source grounding, faithfulness, uncertainty, reviewed routing terms, and L3 usefulness;
- record at least one limitation;
- state explicitly that semantic quality was not automated.

These are authored assertions. The validator checks presence, binding, coverage, and affirmative state; it cannot verify that the reviewer was insightful or truthful. Independent human/domain review remains appropriate.

## 4. Prepare external query gold

Copy `assets/query-gold-template.json` outside the repository and author cases using `contracts/query-gold.v2.schema.json`. Gold must be written from the authorized source and intended tasks, not generated by observing router output. Each case supplies expected route status, ordered expert IDs, and ordered source chunk IDs. Optional 1–5 human scores cover route relevance, sparse-context sufficiency, and source grounding. The harness never invents missing scores.

Do not include source passages in the gold. Queries may themselves be private; the generated report omits query bodies.

## 5. Evaluate

If artifacts were authored directly in the workspace:

```bash
python3 scripts/real_material_trial.py evaluate \
  --workspace /private/local/trial-workspace \
  --query-gold /private/local/query-gold.json \
  --report /private/local/trial-report.json
```

If artifacts are maintained as an external bundle containing `records/`, `l3/`, `shared-core.md`, and `semantic-review.json`:

```bash
python3 scripts/real_material_trial.py evaluate \
  --workspace /private/local/trial-workspace \
  --authored /private/local/authored-bundle \
  --query-gold /private/local/query-gold.json \
  --report /private/local/trial-report.json
```

A fresh one-shot form is also available:

```bash
python3 scripts/real_material_trial.py run \
  --source /authorized/local/material \
  --authored /private/local/authored-bundle \
  --query-gold /private/local/query-gold.json \
  --workspace /private/local/new-trial-workspace \
  --report /private/local/trial-report.json \
  --chunk-lines 80
```

The report contains no source/query bodies or absolute workspace path. It separates:

- `structural_evidence`: coverage counts, query execution, status/exact-route accuracy, expert recall, source-load recall/exactness, and hash verification;
- `authored_semantic_evidence`: review-contract presence, gold authorship, supplied human-score count/averages, and `semantic_quality_automatically_scored=false`;
- `query_results`: privacy-minimized per-case comparisons;
- `failures`: case ID, mismatch kind, and stable code only.

Exit `0` means no comparison failures, `1` means a report was produced with mismatches, and `2` means a contract/lifecycle error prevented a valid evaluation.

## Acceptance and retention

Before calling a real trial useful, inspect every mismatch, review low or absent human scores, sample loaded chunks against the source, and document who authorized the source and who reviewed semantics. Store private workspaces/reports according to the source's access policy. Do not commit them here. The repository's custom source-available license does not grant rights to any trial source or externally authored derivative.
